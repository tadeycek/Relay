## What is wired
- `DesktopMailboxTransport`: live `signal` frames (NIP-17 gift-wrapped `MailboxProtocol.signalFrame`, `SignalMode.LIVE`), first invite additionally stored via `/v1/send` with `urgent:true` (only `CALL` invites; 16 KiB `MAX_SIGNAL_BYTES` bound, over-size refused before any send; later packets never stored); received signals and stored `TYPE:CALL` deliveries go to `callRouter` (call host), not the chat inbox; stored invite acked/deleted only after the host handled it (failed handling is kept for a retry, then dropped); expiry honoured by the engine. `fetchIce`: NIP-98-signed `GET /v1/call/ice?device=<enrolled device id>` with the device key, bounded body, replies after cancel dropped, no credential/SDP/ICE logging.
- `DesktopCallService` (new): sender filter before `onWire` (own identity, or QR-verified, non-blocked, non-deleted contact), start refused with an honest message while unlinked/offline, hang-up flushed before close.
- `DesktopEngine.stop()`: hang up → cancel timers/TURN → close peer → then stop transport. Window close keeps a live call alive (minimises); app exit closes the engine (`CallLifecycle`).
- UI (`DesktopCallComposables`, `DesktopChatUi`, `Main`): Call button in the real `ChatScreen` thread header for eligible direct contacts only (not groups, disabled during a live call); incoming ring card + separate always-on-top ring window; in-call bar with state/timer/Mute/Hang up; call-log rows rendered as centred notes. Log rows come from a local `calls` table flag (`DesktopMessageStore.recordCall`), never from message text, so remote text cannot forge one (cf. `app/.../calls/CallRecord.kt`).
- Diagnostics only: `--demo-call` (requires `--show-chat-ui` and explicit dirs) seeds a demo contact and renders a fixed in-call state; not a real call.
