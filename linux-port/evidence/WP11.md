## Wire shapes the clients must use

**Credentials** — request `GET /v1/call/ice` (optionally `?device=<id>`), NIP-98 header signed over the exact URL
and method `GET`, no body. Success `200`:

```json
{"v":1,"iceServers":[{"urls":["stun:stun.cloudflare.com:3478"]},{"urls":["turn:turn.cloudflare.com:3478?transport=udp","turn:turn.cloudflare.com:80?transport=tcp","turns:turn.cloudflare.com:5349?transport=tcp","turns:turn.cloudflare.com:443?transport=tcp"],"username":"…","credential":"…"}],"expiresAt":1790000000000}
```

(URL list shown is what the faked provider answer produced after the port-53 URLs were removed; the live URL set
is whatever Cloudflare returns.) `expiresAt` = epoch ms, at most 600 s after mint; fetch again for an ICE restart
that outlives it. Errors: `{"v":1,"error":{"code":…,"retryable":…}}` with `rate_limited` 429 (retryable),
`upstream_failed` 502 (retryable), `not_configured` 503, `auth_*` 401, `not_allowed` 403 (full table in
PROTOCOL.md).

**Call invite wake** — an ordinary `POST /v1/send` whose single call-invite delivery adds `"urgent": true`:

```json
{"v":1,"deliveries":[{"to":"<callee pubkey>","id":"<delivery id>","envelope":"<gift wrap>","urgent":true}]}
```

Reply is the unchanged `{"v":1,"results":[…]}`. `429 rate_limited` (retryable) means nothing was stored: resend the
same `id`/envelope after ≥3 s. Only one urgent delivery per request, never to your own identity. The callee's FCM
data message is `{"type":"wake","urgent":"1"}` (high priority, TTL 45 s, no collapse key); a client that sees
`urgent=1` should connect the socket and read the inbox, then ring only for an invite whose own `expires` is still
in the future (the server does not age out the stored invite).

**Call signals** — socket frame `{"type":"signal","to":"<pubkey>","envelope":"<…>","ref":"<opt>"}`; the recipient's
sockets get `{"type":"signal","from":"<pubkey>","envelope":"<…>"}`. Envelope ≤ 16,384 UTF-8 bytes, ≤ 120/min per
socket, not stored. `to` may be your own identity (reaches your other devices). Kotlin note: the test client
`client/mailbox-client.ts` (not part of this WP's ownership) has no `urgent` field on its `Delivery` type yet.

  (the spec does not ask for it; not built) were not touched.

## Open items / deviations

1. **AC3** deployed live `ice` call: not done (needs owner approval to set secrets and deploy).
2. **G4 server call record**: `urgent` is bounded by per-recipient (1/3 s), per-sender (6/min) and global (60/min)
   budgets, one per request, never to self, 45 s FCM life. It is **not** tied to a server-side call record, and the
   server cannot verify the envelope is really a `CALL_INVITE`. Fully meeting G4 needs a client-supplied call id
   and a short-lived table (protocol change for WP12/13). Budgets are in memory and best effort.
3. **Stored invites do not expire early**: the stored delivery lives until acked or 8 days; only FCM drops a late
   wake. Receivers must enforce the invite's `expires`.
4. **Spec deviations** (05 §5): credential TTL 600 s instead of 3 h, per-caller cache 60 s instead of 10 min, as
   instructed for this task and required by G4's short-lived credentials. 05 §5 should be updated by the plan owner.
5. **Signal rate limit is per socket**, so an identity with 4 sockets can relay up to 480/min in total. Unchanged.
6. The 429 for an over-budget urgent send fails the whole request (other deliveries in it too); clients should send
   the invite alone.
7. The ICE host allowlist is `*.cloudflare.com`; a provider that moves TURN to another domain would produce
   `upstream_failed` until the pattern is updated.

## Review fix (2026-10-24, parent)

Independent review found one blocker: the urgent budget was checked in `handleSend` **before** `sendWithMedia`
awaited each blob's `attachCheck` RPC, and only spent once the message was stored, so concurrent urgent sends
carrying a media reference all passed the gate before any of them recorded a spend — a push-wake flood the
budgets exist to prevent.

Fixed: the authoritative check-and-spend now runs inside the same synchronous `sendStored` section that inserts
the messages (the early check stays only as a cheap rejection). Regression test `test/urgent-concurrency.test.ts`:
ten simultaneous urgent sends of one blob — exactly one stored, nine `429`. Mutation check: removing the in-section
check fails it with `expected 10 to be 1`.

Also fixed by the same review: `05-protocol-changes.md` §5 still describes the older TTL; `PROTOCOL.md` and this
file carry the implemented 600 s value, which is what G4's short-lived-credential requirement and the WP02 live
run support.

Open, not fixed: a `:053`/`:00053` port is not stripped by the port-53 filter (it compares the string), the G4
call-record requirement is still unmet (bounded by budgets only), a call longer than 10 minutes depends on the
client doing an ICE restart with fresh credentials, and the rate limiters are in-memory so they reset on eviction.
