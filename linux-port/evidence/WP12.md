## Wire format (`TYPE:CALL|J:<standard padded base64 of UTF-8 JSON>`)

All integers are plain JSON numbers (no fraction/exponent, <=15 digits); ids and keys are lowercase hex; unknown keys,
duplicate keys, unknown `v`, unknown `op`, trailing bytes and non-UTF-8 are rejected. The parser is the in-package
`StrictJson` (not `org.json`: it is lenient and differs between Android and desktop).

Header, in this key order, in EVERY packet (G4: caller, callee, device, call id, nonce, expiry, media mode):

| key | type / rule |
|---|---|
| `v` | `1` (anything else -> `UNKNOWN_VERSION`) |
| `op` | one of the ops below |
| `call` | 32 lowercase hex |
| `ts`, `expires` | epoch ms; `0 < expires-ts <= 60000` |
| `caller`, `callee` | 64 lowercase hex pubkeys, different |
| `device` | the SENDING device: `primary` or 32 lowercase hex |
| `nonce` | 32 lowercase hex, unique per packet (also per invite resend and per candidate batch) |
| `media` | `"audio"` only |

Per-op fields (after the header) and who may send:

| op | extra fields | sender | `to` |
|---|---|---|---|
| `invite` | - | caller | broadcast (no `to`) |
| `ringing` | `to` | callee | directed |
| `accept` | `to` | callee | directed |
| `offer` | `to`, `gen`, `sdp` | either (restart) | directed |
| `answer` | `to`, `gen`, `sdp` | either | directed |
| `ice` | `to`, `gen`, `cands:[{mid,idx,cand}]` (1..20) | either | directed |
| `answered_elsewhere` | `winner`, `reason?` (`answered`/`declined`) | caller, or callee to ITS OWN identity (self-signal) | broadcast |
| `decline` | `to`, `reason?` | callee | directed |
| `busy` | `to`, `reason?` | callee | directed |
| `cancel` | `reason?` | caller | broadcast |
| `end` | `to`, `reason?` | either | directed |
| `timeout` | `reason?` | caller | broadcast |
| `mute` | `to`, `muted` | either | directed |

`sdp` = base64(zlib-deflate(SDP)); inflated size <=16384 bytes, strict UTF-8, starts with `v=0`, only `\r \n` and printable
characters. `gen` 0..1000 (negotiation generation; 0 initial, +1 per ICE restart). Candidate: `mid` `[A-Za-z0-9_-]{1,16}`,
`idx` 0..7, `cand` starts `candidate:`, 10..256 chars of printable ASCII. `reason` `[a-z0-9_]{1,32}`.
`group_start`/`group_end` are rejected as `UNKNOWN_OP` (WP15+).

Bounds (all asserted): wire <=4096 chars, decoded JSON <=3072 bytes, inflated SDP <=16384 bytes, <=20 candidates and
<=256 chars each, parser depth <=4 / <=24 members / <=64 array items / <=4096 chars per string.

Receive rules (`CallBodyCodec.decode`, never throws; result `Ok(packet)` or `Rejected(reason)`), in this order:
`NOT_CALL_BODY`, `TOO_LARGE`, `BAD_ENCODING`, `BAD_JSON`, `UNKNOWN_VERSION`, `UNKNOWN_OP`, `MISSING_FIELD`, `UNKNOWN_FIELD`,
`BAD_FIELD`, `UNSUPPORTED_MEDIA`, `LIFETIME_TOO_LONG`, `FUTURE_DATED` (`ts > now+skew`), `EXPIRED` (`now > expires+skew`),
`WRONG_BINDING`, payload checks (`BAD_SDP`, `SDP_TOO_LARGE`, `TOO_MANY_CANDIDATES`, `BAD_CANDIDATE`), then `REPLAY`
(replay memory is written only after everything else passed). Skew is `CallReceiveContext.skewToleranceMs` (default 10 s).
Binding uses the AUTHENTICATED sender (`senderPubkey`), never a body field: self and sender must be the two parties; op
direction is enforced; the only accepted self-addressed packet is the callee's `answered_elsewhere`.

### Sizes (WP12-AC3)

Measured by a throwaway probe test (deleted afterwards): synthetic 963-byte audio SDP -> offer wire **1,588** chars;
a 2,097-byte SDP with 12 inline candidates -> **1,880** chars; an `ice` packet with 20 short candidates -> **3,156**
chars; 20 candidates of 250 chars split by bytes into 9 + 9 + 2 candidates, largest wire **3,928**; all <= the 4,096 cap.
WP02 (`evidence/WP02.md`) measured wrapped signal frames: plain body 1,716 -> 7,462-byte frame, 4,952 -> 14,290 bytes
(<=14 KiB = 14,336; envelope limit 16,384). Because the cap (4,096) is below the largest measured specimen (4,952), every
packet this codec accepts or emits is at or under that measured frame size. **Limits of this claim:** the test
`wp12Ac3RepresentativeOfferAndAnswerStayWithinTheMeasuredEnvelopeBudget` asserts the plain wire size against the WP02
table; it does NOT run HPKE/NIP-17 wrapping (not in `:core`), and the SDP is a synthetic libwebrtc-style template, not
the recorded real WP02 SDP (that lives in git-ignored `.local`, which was not read). Re-measure with Android-generated
SDP and real wrapping (WP02 already says so) before closing G4.

## Transition table (`CallEngine.handle`; one test per row in `CallEngineTest`, names `<from>_<trigger>_<to>`)

| From | Event | To | Effects (besides `StateChanged`) |

| RingingOut | `ringing` | RingingOut(calleeRinging) | `StartRing(outgoing)` once |

| Connecting/Active (caller) | later `accept` from device X != D | same | `answered_elsewhere(winner=D)` again, once per X (<=8) |
| RingingOut | `decline` / `busy` | Ended DECLINED / BUSY | `StopRing`, cancel timers, record |
| RingingOut | `HangUp` | Ended CANCELLED | broadcast `cancel`, record |
| RingingOut | `RING_TIMEOUT` | Ended NO_ANSWER | broadcast `timeout`, record |
| RingingOut | `INVITE_RESEND` | same | invite (LIVE, fresh nonce, original expiry) while `now < expiry`, re-arm |
| Idle/Ended | `invite` (fresh, allowed peer) | RingingIn | `StartRing(incoming)`, `ringing(to=caller device)`, `RING_TIMEOUT` = min(45 s, expiry-now) |

## Property-style / table tests

`CallEngineFuzzTest`: 600 seeds x 400 random events (valid-looking and hostile packets from three identities, five
devices, four call ids, random timers/peer events, clock jumps up to 70 s) plus one 20,000-step run, with checks after
every step: <=1 open peer connection, <=1 ring, no resource of a different call alive, nothing left open/armed/ringing
after `Ended`/`Idle`, no effect for a call still in the ended-call memory, one `StateChanged` per batch and last, one
`Ended` per call, every `SendSignal` encodable, engine's armed-timer count equals the effect-derived count, all buffers
within their caps. Coverage guards in the test: >300 ended calls, >100 records, >50 steps in `Active`. Table tests: glare for
all 4x4 call-id pairs both command orders (<=1 live call), 6 accept-order permutations of 3 callee devices (exactly the
first accepter wins; losers end `LOST_RACE` with no record), glare both orderings over a two-party bus (lower id survives,

## Decisions where the docs were ambiguous

1. **`device` always means the sending device.** 05 §6 used `from_device` on `invite` and `device` for "the callee's
   device" elsewhere. One header field is needed for binding, so `device` = sender; the target is a separate `to`.
2. **`to` on every directed packet.** Signals reach all sockets of an identity, including the caller's own other
   devices; only a `to` lets those ignore a callee's `accept/answer/ice`. Broadcast ops (`invite`, `cancel`, `timeout`,
   `answered_elsewhere`) must not carry `to` (codec enforces both directions).
3. **`expires` is an absolute epoch ms** (spike metadata used relative 45000). Absolute binds the validity window to the
   packet; invite `expires = ts0 + 45 s`; other packets `ts + 60 s`; hard cap 60 s on `expires-ts`. Resent invites keep the
   original `expires` so a resend never extends ringing.
4. **Skew tolerance is a parameter** (`skewToleranceMs`, default 10 s) applied to both future-dating and expiry.
5. **Op set.** The doc lists `decline/busy/cancel/end/timeout` (+`mute`); all implemented. `group_start/group_end` are out
   of scope and rejected as unknown. Added `gen` (negotiation generation) to offer/answer/ice so duplicate/stale offers and
   restart collisions are decidable; not in the doc.
6. **Self-signal for decline.** G4 requires an authenticated self-sync for the winner; the docs do not cover a device
   that declines. Decline sends `decline` to the caller AND `answered_elsewhere{reason:"declined"}` to the own identity so
   siblings stop ringing silently (no new op). Siblings never end an already-Connecting call from a self-signal.
7. **Glare** (06 §2): lower call id wins by lexicographic compare of the lowercase hex; the loser cancels (`reason=glare`)
   and auto-accepts. A glare-cancelled call is not recorded as missed on sibling devices.
8. **Who restarts ICE.** The doc says "the engine runs an ICE restart" without a side. Either side may; on offer
   collision the original caller keeps its offer and the callee yields (callee = polite peer). A restart offer from the
   peer does not set `restarting` (ICE may never emit a new `CONNECTED`).
9. **Candidate batching.** Doc says 250 ms and 20 per frame; WP02 says split by bytes. Implemented both (`splitIce`),
   plus 64-candidate buffers. The empty end-of-candidates marker is rejected by the codec (host drops it).
10. **Size cap 4096 chars** (not 14 KiB of plain body): chosen below the largest WP02-measured specimen (4,952 chars ->
    14,290-byte frame) so the 14 KiB wrapped target holds without a server limit change. This is a conservative reading of
    one measurement, not a proof for other SDPs.
11. **Replay memory** keyed by (authenticated sender, nonce), bounded at 256 (oldest evicted); recorded only after a
    packet passed every other check. Eviction is safe because stale packets die on `expires`.
12. **Ring/ended id memory:** the last 16 ended or busied call ids are remembered so a late/duplicate invite cannot ring
    again; older ids are forgotten (the freshness window is the second line). `StartCall` never reuses a remembered id.
13. **Lost accept race** ends with outcome `LOST_RACE` (silent) after `answered_elsewhere` or after 5 s without offer;
    `ANSWERED_ELSEWHERE` is used while still ringing. Neither writes a missed-call record (LP-D10).

## Review fixes (2026-10-24, parent)

Independent review found three blockers; all are fixed here test-first, each with a mutation check.

| Finding | Fix | Test / mutation |
|---|---|---|
| Replay-nonce cache evicted the oldest **unexpired** entry, so an attacker could push a live nonce out and then replay its packet | a full guard now REFUSES new nonces instead of discarding live ones, plus a per-sender cap (`perSenderCapacity`, default 32) so one identity cannot fill it | `replayGuardMemoryIsBoundedAndForgetsExpiredEntries` (fills from several senders to defeat the sender cap) — fails when eviction is restored |
| `busy` from ONE callee device ended the whole call, contradicting LP-D10 (every device rings, first accept wins) | `Busy` in `RingingOut` is recorded (`busySeen`) but not terminal; the call ends `BUSY` at the ring timeout, or connects if another device accepts | `ringingOut_oneBusyDeviceDoesNotEndTheCall`, `ringingOut_nobodyAnswers_endsBusyAtRingTimeout`, `busy_inviteWhileInAnotherCall` — the first fails when busy is made terminal again |
| The winning callee device never told its own identity it had won, so a sibling depended on the caller's LIVE-only `answered_elsewhere` and could ring to timeout, recording a call that was answered | after the caller's first `Offer` the winner sends `AnsweredElsewhere(self)` once (`announcedWinner`) | `calleeReceivesCallerOffer_tellsItsOwnIdentityItWon`, `siblingWhoGetsThatSelfSignalStopsRinging` — the first fails when the announce is disabled |
