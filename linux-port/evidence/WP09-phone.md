## Implemented phone surface (before mutation run)

- Pure blocking `PhoneFileEngine`, injected `PhoneFileStore`, `PhoneFileNetwork` and app-private `PrivateFileSpace : FileStaging`; production explicitly supplies this staging to shared `FileSender` and `FileAssembler`.
- SAF source read once with 64 KiB reads and a cap-plus-one overflow probe, without trusting provider sizes or requiring seeking. Unknown/lying-size streams use their actual observed size. Fresh per-file key and per-part IV are generated by shared FileSender once; completed ciphertext is fsynced and retained for exact retry.
- `phone_files` durable structured record plus a chat bubble retaining the exact authenticated manifest/original payload id; full plaintext SHA-256 and size verified before readiness/publication. SQLCipher handwritten additive v25→v26 migration. No Room.
- Stable ordered digest lists in `file_media_refs`; platform `Transport.sendWithMedia` override puts refs in the signed POST body and checks immutable refs on retries. Existing group file sending is explicitly disabled/deferred, with safe group receive/SENT placeholders rather than raw manifest text. Existing photo/group APIs remain present.
- Incoming direct and SENT file adapters use the original RelayPayload id, not the outer sync event id. Part hash/length progress is durable; missing/corrupt persisted parts are fetched again, while valid completed parts survive restart. Assembly validates raw RLYF v1 framing/tags, whole digest/size and original id before publishing a private verified source.
- New streamed mailbox paths use `MailboxMedia.Client(RequestContext(AndroidNostrSigner { PhoneDeviceEnrollment.authKeys(...) }, "primary"))`, not raw identity auth after migration. Upload recipients include contact plus own identity. Explicit cancellable upload/download/confirm seam; confirmation bits persist and retry without redownloading.
- SENT publication carries the same top-level `media:[stored ciphertext digests]` on every server part/retry. File SENT work runs even without a linked-device hint. A durable `sync_granted` receipt is written only after publication acceptance, never merely because its outbox row disappeared. Originating-device confirmation waits for that receipt. This matches the server agent's relayed contract, including max8 distinct lowercase digests. The phone unit late-enrollment test is a **model adapter**, not an independent real server proof.
- Default-off `-PrelayFileSend=true` build opt-in, checked in controller and picker; direct SAF OpenDocument plus explicit send confirmation. Receive is independent of this flag. File bubble shows name, bytes, part progress, retry/cancel and verified Save as/Downloads/Open actions. Database message enum remains TEXT for compatibility; the separately persisted phone_files record and FileBubble renderer distinguish a file from caption-only text.
- Downloads uses MediaStore pending publication; SAF export explains that atomic rename is not guaranteed, deletes failed outputs where possible and reports cleanup failure. Only a verified private source may be exported. Open is explicit, warns first, refuses executable-like content, grants read-only content URI permission, and uses a separate narrow `cache/file-open/` FileProvider root containing verified copies only.
- Owner-only files/directories, CREATE_NEW/private random paths, symlink refusal, 512 MiB private-space budget and conservative staging reservation. SQL admission permits one unfinished transfer to reserve transient storage; excess incoming work remains unhandled/replayable instead of consuming unbounded reservations. Deletion/retention fences state and outbox work; cancelled ids cannot be retried into existence. Existing runtime ticks handle transfers/cleanup; no new service.
