## Row measurements (`EXPOSE_METRICS=1`)

The scripted five-participant create/join/leave sequence in `test/callroom.test.ts` printed:

```
WP15-ROWS create=4 join=25 leave=5 total=34
perJoin=[{"read":6,"written":5},{"read":7,"written":5},{"read":10,"written":5},{"read":13,"written":5},{"read":16,"written":5}]
```

- **Writes:** create 4; each join 5 (25 for five joins); the leave sequence 5; **34 total**.
- **Reads:** 6, 7, 10, 13 and 16 for the five joins as the roster grows. The create read count is not printed
  by the test; only its 4 writes are.
- The join cost is the participant row plus its identity index, the room's auth-replay row plus its expiry
  index, and the roster/secret reads. LP-D13's "at most one row per participant" is satisfied in the
  `participants` table itself: one row per pid. The auth-replay row is one extra row per authenticated request,
  bounded by the per-room join/SFU budgets and pruned by `expires_at` on each `recordAuth`. The room's storage
  is deleted on teardown, so a dead room holds no rows.
- The header `x-relay-sql-rows: read=…;written=…` is set on every response, including the 101 upgrade. The
  test reads it from the upgrade response's headers.
- The numbers are from the workerd test runtime, not the deployed Worker. They measure SQL rows, not DO
  requests or CPU time. A production 5-person call's request count is the subject of WP16's dashboard check.

## Exact client contract

The full shapes are in [PROTOCOL.md](../../server/cloudflare/PROTOCOL.md#group-calls-wp15). The client needs:

| Step | Request | Notes |
|---|---|---|
| Create | `POST /v1/call/rooms` with `{"v":1,"room":"<32hex>","secretHash":"<64hex>"}` | NIP-98 over the exact URL. `secretHash` = lowercase hex SHA-256 of the 32-byte join secret. `200 {"v":1,"created":true}`; `409 room_exists` if the room already has a different hash. |
| Existence | `GET /v1/call/rooms/<room>?device=<id>` | `200 {"v":1,"room":"…","participants":n,"createdAt":ms}` or `404 not_found`. The only query parameter is `device`. |
| Join | `wss …/v1/call/rooms/<room>/ws?secret=<64hex>&device=<id>&pid=<16hex>` | NIP-98 over the `wss://` URL. `pid` is optional on the first join; supply it to reconnect within 30 s. The first server frame is `{"type":"welcome","v":1,"you":"<pid>","participants":[…other participants…]}`. |
| Frames | `{"type":"heartbeat"}`, `{"type":"state","muted":bool,"deafened":bool?}`, `{"type":"leave"}`, `{"type":"end"}` | `end` is creator-only. Unknown types get `{"type":"error","code":"bad_request"}` and keep the socket open. |
| Roster | `joined`, `left`, `state`, `end` frames | The room broadcasts them to the other participants. The payloads are in PROTOCOL.md. |
| SFU | `POST` or `PUT /v1/call/rooms/<room>/sfu/<op>` with `{"v":1,…}` | `<op>` is `sessions-new`, `tracks-new`, `renegotiate` or `tracks-close`. The caller must have an open room socket and may only name its own session id (current, or previous within 30 s). |
| Close | `1000` normal; `4003` no attachment; `4009` replaced or revoked | A dropped socket keeps the pid for 30 s. The last participant's leave tears the room down; a dropped last socket does so on the 30 s alarm. |

The SFU bodies are narrowed to the provider's shape. A local track is exactly
`{"location":"local","mid":"<id>","trackName":"mic"}` (one per request). A remote track is
`{"location":"remote","sessionId":"<publisher session>","trackName":"mic"}`; the publisher must be another
participant currently in the room. The response is reduced to `v`, `sessionId`, `tracks` (`mid`,
`trackName`), `sessionDescription` and `requiresImmediateRenegotiation`.

The raw join secret is never stored. The DO stores the SHA-256 and compares the presented secret in constant
time. The SFU secret (`SFU_APP_SECRET`) is read from the Worker env on each request and never appears in a
response, a log line or SQLite. The tests spy all four console methods and the stored room row.

## Limits

| Limit | Value | On breach |
|---|---|---|
| Participants per room | 17 | `409 room_full` |
| Reconnect grace for a dropped socket | 30 s | room tears down |
| Joins per room per minute | 60 | `429 rate_limited`, retryable |
| SFU operations per identity per room per minute | 120 | `429 rate_limited`, retryable |
| Create/end/existence body | 8 KiB | `413 request_too_large` |
| SFU request body | 64 KiB | `413 request_too_large` |
| SFU SDP string | 16 KiB | `400 bad_request` |
| Tracks per SFU request | 64 | `400 bad_request` |
| SFU provider response | 256 KiB | `502 upstream_failed`, retryable |
| SFU provider deadline | 15 s | `502 upstream_failed`, retryable |

All are `Limits` fields with env overrides in `src/protocol.ts`; the tests set smaller values on the live DO
instance where needed. The SFU provider timeout in teardown is additionally capped at 2 s, and the whole
teardown track-close batch races a 3 s budget.

## Open items and risks

1. **Reconnect now calls the Mailbox membership/revocation RPC.** The review found that the 30 s pid
   reconnect fast path trusted the stored row and skipped `callAuth`, so a device revoked just before the drop
   could rejoin. The fix calls `callAuth` once per rejoin and refuses a revoked/non-member signer. The earlier
   "cross-DO RPC hung in the harness" concern did not reproduce: the fresh-join path performs the same RPC in
   the same tests, and the new B2 test passes. A heartbeat-only socket is also rechecked at most once per 12 s
   and closed `4009` when the check fails.
2. **The join secret travels in the WebSocket URL query**, as the protocol specifies. It also appears inside
   the signed NIP-98 URL, so capturing request headers leaks it as well. The Worker and DO never log the query;
   the edge request logs are outside this code and may capture the URL. Moving the secret to a header is not
   possible for browser WebSockets; a first-frame secret would need a different handshake. The secret is per
   room, short-lived and delivered E2E. This is documented in PROTOCOL.md next to the endpoints.
3. **`GET /v1/call/rooms/<room>` returns `createdAt`, not `last_activity`.** The `last_activity` column is set
   at create and not updated; the 10-minute "voice active" banner timer is client-side. Heartbeats are
   keepalives and do not write rows. If the server should expire stale banners, update `last_activity` on
   join/leave/state (one extra row write per event).
4. **One provider session per participant device, not one per room.** The SFU has no rooms; the `CallRoom` is
   the directory. The task's "creates a Cloudflare Realtime SFU session for a room" is implemented as one
   session per participant in that room, matching `07 §1`. There is no room-wide SFU session to create.
5. **Auth-replay rows are extra rows per request.** The `participants` table has one row per participant, but
   the replay table adds one row per authenticated request. The measured 5 writes per join include the replay
   row and its index. The table is pruned by `expires_at` and wiped on teardown. If the "at most one row per
   participant" reading includes replay rows, remove the replay table and rely on the NIP-98 60 s window plus
   the per-room rate limits; that weakens replay protection.
6. **No live provider error-shape check.** The proxy maps any provider `errorCode`/`errorDescription` in a
   `tracks/new` response to `502`. The live provider's exact error envelope for every failure mode was not
   re-checked here; WP02's spikes covered the happy path and some errors. A live call should confirm the
   mapping.

## WP15 review blocker fixes

The independent review found six blockers while the pre-existing suite was green (396/396). Each was fixed
test-first; the RED result below is what the probe/failing test actually printed before the fix, and the
GREEN result is the final full run.

| Blocker | Fix | Regression test | RED observed |
|---|---|---|---|
| **B1** duplicate join/reconnect ghost-marks the live participant | `webSocketClose`/`webSocketError` remove only when no other live socket for the pid remains (the closing socket is excluded), and `handleUpgrade` accepts the replacement socket before closing the old one | `B1: duplicate join keeps the participant active and schedules no teardown alarm` | Reviewer probe: `PROBE-DUP rows [{"left_at":1792864280048}]`; `PROBE2 alarm-ran true existence 404` while the new socket was open |
| **B2** pid reconnect fast path skipped `callAuth` | the pid path now calls `callAuth` once per rejoin and refuses revoked/non-member signers | `B2: refuses a revoked device rejoining with its old pid` | Reviewer probe: `PROBE-REVOKE-REJOIN status 101` (expected 401) |
| **B3** heartbeat returned before the revocation recheck | heartbeat performs a throttled `callAuth` (12 s default, `CALL_HEARTBEAT_RECHECK_MS`); failure closes `4009` before removal so teardown cannot mask it with `1000` | `B3: closes a revoked heartbeat-only socket within the throttle and removes it from the roster` | Reviewer probe: `PROBE-REVOKED-LISTEN closed null` while revoked |
| **B4** `removeParticipant` never closed the provider track | every removal path (leave, close, error, revocation) best-effort `tracks-close` for the stored session/mid within the 2 s/3 s budget; failures are a counter | `B4: closes the provider track when a participant leaves`; `B4: closes the provider track on revocation` | Reviewer probe: `PROBE3 upstream-calls-before 2 after 2` (no `/tracks/close`); the B4 tests initially failed with `expected false to be true` |

Cost: the active-room alarm is **1 alarm write + <= 17 Mailbox `callAuth` reads per 12 s per active room**, 0
participant-row writes when healthy, so a 5-person call is ~5 RPCs per 12 s. The create limiter costs 1 Mailbox
SELECT COUNT + 1 INSERT + 1 pruning DELETE per create (rows bounded to ~30 per identity per minute, pruned on create).
In-memory limits (join/provider-op budgets, `tails`) reset on DO eviction; the create budget does not.

Mutation checks (tests were already green on first run for the new ones, so these are mutation checks, not RED):
disabled alarm recheck -> idle-revoked test fails; removed `pending_track_close` insert -> retry test fails;
removed create-limit `return false` -> distinct-room test fails. All restored byte-for-byte (diff verified).
