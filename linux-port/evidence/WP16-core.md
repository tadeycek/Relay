## Contract and handoff

- `com.relay.app.call.group.GroupCallCodec.newStart(roster, caller, device, now, random)` mints room (16 bytes), join secret (32 bytes), event id (16 bytes); `newEnd(start, now, random)` binds the same room. Supply a CSPRNG callback (`(Int) -> ByteArray`), not a seeded test RNG. Version-1 JSON `encode` is **plaintext for the E2E sealer only**: never send/log it as an unsealed mailbox or room message. Send as stored `TYPE:CALL` fan-out to each group identity. `decode(wire, authenticatedSender, currentRoster, epochMillis, replay)` takes the identity verified by the E2E seal, never body `caller`; rejects malformed, oversized (>2048 UTF-8 bytes), stale/foreign roster, unauthorized sender, expired/future event and duplicate event id. The exact key set includes `v,op,event,group,owner,revision,rosterHash,room,joinSecret,caller,device,created,expires` and optional `keyEpoch` (future WP17 metadata only). End has null secret. Roster hash binds sorted member identities, group id, owner and revision (not mutable display labels); it is **not a signed roster**.
- `GroupCallEngine(initialRoster, selfPubkey, clock)` is separate from 1:1 `CallRuntime`. Host serializes calls to `apply(announcement, authenticatedSender)`, `updateParticipants(list)`, `updateRoster(state)`, `tick()`, `mute(bool)`, `deafen(bool)`, `leave()` and applies ordered `GroupCallEffect`: OpenRoom, CloseRoom, Subscribe/Unsubscribe (pid + sessionId + track), WarnUnknown, SetMicrophoneMuted, SetPlaybackDeafened. Call `tick` on timer and after reconnect. A lower `(created,room)` wins competing starts locally; only the authenticated starter can end the active room. Revision change closes locally; removed self cannot rejoin old revision. A participant absent from the local roster is warned and not subscribed, **not server-authorized by this check**. Local close is a request to the host to tear down peer/socket/subscriptions, not proof of remote SFU cleanup. Mute effect is a state hint; host must keep packets flowing, measure the 30-second no-packet expiry and republish if needed. State label remains `Group calls are encrypted in transit, not end to end.`.
- The host must persist a replay fence/ended-room identity across restart or revalidate current authorized live state before reopening a stored invite. This in-memory bounded cache is not a durable server authorization or an atomic create-if-absent contract. Room expiry is a control-message bound, not permission to tear down an otherwise confirmed live room without a renewed authenticated announcement. Version/retention policy needs agreement with WP15/clients.

## Third-context review fixes (core-local)

Closed in `:core` (`call/group/**`), each with a regression test:

1. **End-before-start fence** — `group_end` records a `(room, caller)` fence even with no active room; a later unexpired start is rejected. Fences expire (`max(end.expires, created+10 min)`), are capped at 256 (new rooms fail closed, nothing unexpired is evicted), and `GroupCallEngine.snapshot()` / `GroupCallEngine(..., snapshot)` plus `GroupEventReplay(initial)` give a persistable fence + replay cache. The replay cache (cap 256) also bounds event flood; full cache rejects new events (fail closed — a flood of 256 valid events in the window can deny later events; host must persist and age the snapshot). Hosts must persist the snapshot atomically with accepted events.
2. **Invite expiry vs established room** — expiry rejects new joins and closes an *unconfirmed* room; `confirmedRoom(room)` (host/server-supplied after authenticated join/live-state readback) keeps it past expiry (test: 20 min). `roomStateUnknown()` fails closed (unsubscribe + close). Unknown/unconfirmed state never keeps a room open.
3. **Secret redaction** — `GroupAnnouncement` and `OpenRoom` have explicit `toString` (`joinSecret=<redacted>`); equality unchanged; `encode`/`secretHash` error messages carry no secret (tests).
4. **Fail-closed participant snapshot** — invalid pid/pubkey/device/session/track, duplicate pids or >17 entries unsubscribe every prior track and close the room (ghost-subscription tests).
5. **secretHash vector** — `0…01` (64-hex text) → `c386d8e8…b767b417` per PROTOCOL.md; hashing decoded bytes is asserted different.
6. **Verified sender** — `decode`/`apply` take `VerifiedGroupSender` (private constructor, `fromAuthenticatedSeal`) instead of a string. **`:core` does NOT verify the E2E seal itself**; any code can call the factory. Android/desktop ingress must construct it only after a verified seal — still a cross-layer blocker.

RED: the engine/codec pieces from earlier contexts existed before the new tests were written, so RED was established by **mutation check, not first-run failure**: decoded-bytes secretHash (2 fail), `tick` ignoring `confirmed` (2 fail), invalid snapshot retained (3 fail), toString leaking (2 fail), fence expiry removed (1 fail). Mutation "remove explicit 256 end-fence cap" **survived** (no test fails): the replay cache (256) already bounds end events, so that guard is defensive/redundant on the end path. All mutations restored (`cmp` identical).

Closed in `:core`:

1. **Backdated start preempts an established call** — a confirmed room is never preempted; two *unconfirmed* starts are tie-broken (lower `(created, room)`) only when `created` differs by ≤ 5 s. Outside the window the existing call stays. Tests: `backdatedStartCannotPreemptConfirmedRoom`, `unconfirmedCallNotPreemptedOutsideTieWindowButInsideWindowLowerWins`.
2. **Valid-event flood** — replay cache and end-fence map get a per-sender quota (12; 17 members × 12 < 256); a sender at quota (or hitting the last slot) evicts its **own** oldest entry instead of refusing everyone. A start is no longer refused because the fence map is full. An end for the ACTIVE room by its starter always closes, even if the replay cache is full. Replay slots are taken only after every other rejection (no burn for rejected events). Tests: `floodOfEndsForRandomRoomsCannotBlockLaterStartOrActiveEnd` (300 ends, then a start and an active end succeed), `restoredFullSnapshotOfForeignEntriesNeitherBlocksStartNorActiveEnd`, `rejectedEventDoesNotBurnReplaySlot`. Residual: a flooder can evict its *own* old fences/replay ids, so it can re-open a room it previously ended itself (it could equally start a new room).
3. **Unvalidated snapshot** — restore validates room (hex32) / caller (hex64) / event-id shape, drops expired, clamps expiries to `clock()+MAX_LIFETIME`, scans at most the last 1024 entries, truncates to caps/quotas, validates `activeRoom`, and never throws (`GroupEventReplay(initial)` truncates instead of `require`). Tests: `restoreOf5000EntriesNeverThrowsAndIsBounded`, `restoreClampsHugeExpiryDropsMalformedKeysAndBadActiveRoom` (Long.MAX_VALUE/MIN_VALUE, malformed keys, bad active room; fresh start accepted; clamped fence lapses).
4. **Participant snapshot ends the call for everyone** — malformed entries and duplicate pids are dropped, the first 17 valid are kept, no `CloseRoom`; only a non-empty snapshot with zero usable entries closes. Tests: `eighteenParticipantsKeepFirstSeventeenWithoutClosing`, `oneMalformedSessionIsDroppedOthersStaySubscribed`; existing `invalidSnapshot…`/`malformedSession…` (single bad entry ⇒ wholly unusable ⇒ close) still pass.
5. **Suggestions done:** `Subscribe` only after `confirmedRoom` (which now returns the pending Subscribe effects; `subscribeIsGatedOnHostConfirmation`, `confirmationForWrongOrExpiredRoomHasNoEffect`); `securityLabel` is a computed property (no field, `copy()` cannot change it; `securityLabelIsConstantNotACopyableField`); any `keyEpoch` is rejected by `encode`/`decode`/`apply` until WP17 (`keyEpochIsRejectedUntilWp17`).
