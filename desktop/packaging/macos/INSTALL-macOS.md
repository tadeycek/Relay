# Relay on Apple Silicon — CI preview, not yet Mac-accepted

This DMG is built without a Developer ID, notarization or App Store review. It is **not a release clearance**: no physical Apple Silicon Mac acceptance run has been recorded. Intel Macs are unsupported. Obtain the DMG and `SHA256SUMS` from the **same** `Desktop macOS Apple Silicon DMG` workflow artifact for the intended commit/tag, from a trusted repository run. Inspect `signing-status.txt` and both `codesign-*.txt` files from that run; the build does not promise an unsigned versus ad-hoc code-signature state before inspection.

1. Verify the downloaded DMG before opening it: in Terminal, from the directory containing the DMG and `SHA256SUMS`, run `shasum -a 256 -c SHA256SUMS`. Stop if the checksum fails or the source is untrusted.
2. Open the DMG and drag Relay to Applications. Try launching it from Applications. If macOS says its developer cannot be verified / Apple cannot check it, and **only** if you trust the exact verified artifact, open **System Settings → Privacy & Security**, scroll down, choose **Open Anyway** for Relay, then confirm **Open**. See [Apple's instructions](https://support.apple.com/en-us/102445).
3. If macOS says the app **will damage your computer**, was moved to Trash, is damaged, or no Open Anyway option appears, **stop**. Do not disable Gatekeeper, clear all quarantine attributes with `xattr -dr`, or override a malware warning. Ask the maintainer to investigate the actual DMG and signing diagnostics. These warnings may require changing the distribution/signing strategy; Open Anyway is not guaranteed to work for this unnotarized JVM bundle.
4. On first use, link from the phone as directed in the app. Confirm the macOS Keychain consent request relates to Relay and approve only if expected. Voice calls may request microphone permission when you accept/join one; review it under **System Settings → Privacy & Security → Microphone**. Neither prompt is proven by the CI diagnostic.
5. On updates, check the new artifact's checksum and provenance again; replace the app without deleting Relay's profile. Gatekeeper or Keychain might prompt again when the app bundle changes. Whether keys and the local DB survive updates remains a physical-Mac acceptance gate; keep a safe backup before attempting preview updates.

The CI `--print-identity` smoke uses disposable runner directories, creates an identity, and exits. It is **not** a `--self-test` (no such CLI exists) and does not prove DB access, Keychain persistence, microphone capture, phone linking, call audio, or a downloaded DMG's Gatekeeper behaviour.
